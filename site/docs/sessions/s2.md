## 1. Why: "it works on my machine" is not a result

Your workflow so far is Colab: open a browser, get a machine with some Python and some packages, run cells until the table appears. Which Python? Which pandas? Whatever Google installed that month. Re-run the notebook next year and the numbers may differ, or the code may not run at all — and you will not know which of the two hundred libraries changed.

For a scientist that is not an inconvenience, it is a validity problem. A result nobody can reproduce, including you in six months, is a claim, not a finding. Journals and data editors now require the replication package to pin its environment (the optional [replication track](../replication.md) is built on exactly this). Three things must be fixed for a Python project to be reproducible:

| Layer | Question | Answered by |
|---|---|---|
| The interpreter | Which Python? `3.12`, not "whatever `python` is" | `.python-version` |
| The direct dependencies | Which libraries did *I* ask for? | `pyproject.toml` |
| The exact resolved set | Which exact versions of those, *and of everything they pull in*? | `uv.lock` |

`uv` is one tool that manages all three, fast, on every platform. It replaces the `pip` + `venv` + `requirements.txt` trio of [last year's lesson](https://github.com/KnuxV/advanced_programming_python/blob/main/lessons/02-python-env.md) (still worth reading for the *why* of virtual environments; the commands differ).

## 3. A project from scratch

### 3.1 `uv init`

Go into your course repository and initialise a project **in place** (no folder name after `init`; the project takes the folder's name):

```bash title="Any terminal"
cd ~/cours-agents
uv init --no-package --python 3.12
ls -a
```

Two flags, both deliberate:

- `--python 3.12` pins the interpreter. Without it, `uv` picks the newest Python it can find — different on every laptop, and your lockfiles would disagree with your neighbour's and with Codespaces.
- `--no-package` gives the simple layout: one `main.py` at the top. (Since uv 0.12 the default is a `src/` package layout with a build system — right for libraries, noise for us.)

Expected files (plus your `.git`, `README.md` and `.gitignore` from Session 1):

```text
.python-version   pyproject.toml   main.py
```

- `.python-version` contains `3.12`. Every `uv` command in this folder uses that Python — downloading it first if needed.
- `pyproject.toml` is the project's declaration: name, the Python requirement, and an empty `dependencies = []` list. This is the standard file every Python tool reads.
- `main.py` is a hello-world.

!!! note "`uv init` inside an existing git repository"
    `uv` notices the `.git` you created in Session 1 and does not create a second one. It also does not write a `.gitignore` in that case — which is why Session 1 made you write one with `.venv/` in it.

### 3.2 `uv run` — the environment appears

```bash title="Any terminal, inside cours-agents"
uv run main.py
ls -a
```

The first run prints a few lines — `Using CPython 3.12.x`, `Creating virtual environment at: .venv` — then `Hello from cours-agents!`. A new folder `.venv` exists. That is the **virtual environment**: a private copy of Python 3.12 plus the packages *this project* installs, isolated from every other project on your machine. You never activate it by hand; `uv run <something>` always runs inside it.

`.venv` is machine-specific and large. It is **never committed** — it is in your `.gitignore`, and `uv` also drops a `.gitignore` inside it as a belt-and-braces. Anyone who clones your repo recreates it in seconds from the lockfile (section 3.4).

### 3.3 `uv add` — declare a dependency

```bash title="Any terminal, inside cours-agents"
uv add polars
cat pyproject.toml
ls -a
```

Three things happened:

1. `pyproject.toml` now says `dependencies = ["polars>=1.44.1"]` — *what you asked for*, with a lower bound.
2. A new file, **`uv.lock`**, lists the *exact* version of polars and of everything polars depends on, with a cryptographic hash of each downloaded file. Open it (`head -20 uv.lock`); you will never edit it by hand, but you will always commit it.
3. Polars was installed into `.venv`.

Check it works:

```bash title="Any terminal, inside cours-agents"
uv run python -c "import polars; print(polars.__version__)"
```

Expected: `1.44.1` (or later, if you add it after this page was written). To remove a dependency: `uv remove polars`. To see the tree: `uv tree`.

!!! quote "`pyproject.toml` is the wish, `uv.lock` is the receipt"
    The first says "I need polars, at least 1.44". The second says "on 18 September 2026 that resolved to polars 1.44.1, polars-runtime-32 1.44.1, these exact files". Both are committed; the receipt is what makes the result reproducible next year.

### 3.4 `uv sync` — reproduce it elsewhere

This is the other half of the story. On any other machine (a classmate's laptop, a Codespace, the university cluster):

```bash title="Any terminal"
git clone https://github.com/YOUR-USERNAME/cours-agents.git
cd cours-agents
uv sync
```

`uv sync` reads `.python-version` and `uv.lock`, fetches that exact Python if missing, and rebuilds `.venv` identically. Same numbers, guaranteed by hashes. (`uv run` does this implicitly too; `uv sync` is the explicit form you put in a README.)

### 3.5 Commit the project files

```bash title="Any terminal, inside cours-agents"
git status
git add pyproject.toml uv.lock .python-version main.py
git commit -m "Initialise uv project with polars"
git push
```

`git status` must **not** list `.venv` — if it does, your `.gitignore` is missing the `.venv/` line; add it before committing.

## 4. From a notebook cell to a script with arguments

### 4.1 The gap this session closes

In a notebook, a parameter is a variable you edit at the top of the cell and re-run:

```python title="What it looks like in Colab"
import polars as pl

CSV_FILE = "sales.csv"      # edit here…
TOP = 3                     # …and here, then Shift+Enter

df = pl.read_csv(CSV_FILE)
result = (
    df.with_columns((pl.col("units") * pl.col("unit_price")).alias("revenue"))
    .group_by("region")
    .agg(pl.col("revenue").sum())
    .sort("revenue", descending=True)
    .head(TOP)
)
result
```

That works for one person, once. It cannot be run on ten files in a loop, scheduled every night, called by a colleague who does not open notebooks, or — in Session 4 — called by an agent that needs to *test* your code. The industry form of the same thing is a **script with arguments**: `uv run report.py sales.csv --top 3`. The values that used to be "edit the cell" are now typed on the command line.

Get the toy data (nine rows, invented; columns `region, product, units, unit_price`):

```bash title="Any terminal, inside cours-agents"
curl -LO https://knuxv.github.io/cours-agents/files/sales.csv
head -3 sales.csv
```

### 4.2 The script

Create `report.py` with the following content (`nano report.py`, paste, ++ctrl+o++, ++enter++, ++ctrl+x++ — or VS Code). Also downloadable: [report.py](../files/report.py).

```python title="report.py"
"""Total revenue per region from a sales CSV. Usage: uv run report.py sales.csv --top 2"""
import argparse
import polars as pl


def main() -> None:
    parser = argparse.ArgumentParser(description="Revenue per region from a sales CSV.")
    parser.add_argument("csv_file", help="path to the CSV (columns: region, product, units, unit_price)")
    parser.add_argument("--top", type=int, default=3, help="how many regions to show (default: 3)")
    parser.add_argument("--product", help="keep only this product (default: all)")
    args = parser.parse_args()

    df = pl.read_csv(args.csv_file)
    if args.product:
        df = df.filter(pl.col("product") == args.product)
    result = (
        df.with_columns((pl.col("units") * pl.col("unit_price")).alias("revenue"))
        .group_by("region")
        .agg(pl.col("revenue").sum())
        .sort("revenue", descending=True)
        .head(args.top)
    )
    print(result)


if __name__ == "__main__":
    main()
```

Read it top to bottom; four ideas carry the whole of `argparse`:

- **A parser** describes what the command accepts. The `description` shows up in `--help`.
- **A positional argument** (`csv_file`) is required and identified by its position: `report.py sales.csv`.
- **An option** (`--top`, `--product`) starts with `--`, is optional, and can have a `default` and a `type`. `type=int` converts the text `"2"` to the number `2` *and* rejects `"two"` with a clean error.
- **`parse_args()`** returns an object; `args.top` is your old `TOP` variable. The rest of the function is the notebook cell, unchanged, with the two constants replaced.

The `if __name__ == "__main__":` line means "run `main()` only when this file is executed as a script, not when it is imported". You will see it in every Python script from now on; type it, do not question it yet.

## 5. Environment variables — where secrets live

### 5.1 What they are

Every program you start receives a small dictionary of named values from the shell that started it: the **environment**. Some are set by the system (`HOME`, your home folder; `PATH`, the folders searched for commands); any you like can be added. Look at yours:

```bash title="Any terminal"
echo $HOME
echo $PATH
env | head -5
```

`$NAME` reads a variable in the shell. Set one for *this window only*:

```bash title="Any terminal"
export GREETING="bonjour"
echo $GREETING
```

Open a second terminal window and run `echo $GREETING` there: empty. `export` affects the current shell and the programs it launches, nothing else. To make a variable exist in every future window, the line goes in the shell's **startup file** — `~/.bashrc` on WSL, Codespaces and Git Bash, `~/.zshrc` on a Mac — which is exactly what [setup section 5.2](../setup.md#52-store-it-as-an-environment-variable) had you do for `UNISTRA_API_KEY`. Confirm it took, in a new window:

```bash title="Any terminal — new window"
echo $UNISTRA_API_KEY | cut -c1-6
```

If that prints an empty line, fix it now (wrong file, or the terminal was not reopened); Session 3 depends on it.

### 5.2 Reading them from Python

```python title="whoami.py"
import os

key = os.environ.get("UNISTRA_API_KEY")
if key is None:
    raise SystemExit("UNISTRA_API_KEY is not set. See the setup page, section 5.")
print("key found, starts with", key[:6])
```

```bash title="Any terminal, inside cours-agents"
uv run whoami.py
```

Expected: `key found, starts with sk-XXX`. `os.environ` is the environment as a dictionary; `.get()` returns `None` instead of crashing when the name is absent, so the script can fail with a *sentence* rather than a `KeyError` traceback. Failing loudly and early on a missing secret is the correct behaviour — an agent reading that message knows what to do; one reading a traceback guesses.

### 5.3 Why the key never goes in the code

Three reasons, in increasing order of seriousness.

1. **Configuration is not code.** The same script runs with your key on your laptop, with a colleague's on theirs, with a test key in CI. Hard-coding it means editing the code to change who runs it. ([The Twelve-Factor App — Config](https://12factor.net/config), two paragraphs, is the canonical statement.)
2. **Git remembers forever.** You learned in Session 1 that a commit is permanent. A key pasted in `report.py`, committed, then deleted in the next commit is *still in the history*, and `git log -p` shows it to anyone with the repository. Bots scan public GitHub for `sk-` strings within minutes of a push.
3. **Agents copy what they see.** In Session 4 an agent will read your files to work on them. A key in the code ends up in its context, its logs, and possibly its next commit.

So: the secret lives in the environment; the code reads `os.environ`; the repository contains the *name* of the variable (in the README: "set `UNISTRA_API_KEY`"), never its value. Some teams put variables in a `.env` file loaded by the `python-dotenv` package instead of the startup file — [last year's lesson](https://github.com/KnuxV/advanced_programming_python/blob/main/lessons/06-organization_packaging/060-var_configs.md) covers it; if you use one, `.env` goes in `.gitignore` (yours already has it) and the same three reasons apply.

!!! danger "If a key was ever committed"
    Deleting it from the file does nothing. Regenerate the key ([setup 5.1](../setup.md#51-generate-the-key)) so the leaked one is worthless, then fix the repository. Come and see us; rewriting history is possible but is not a beginner operation.

## 6. Bonus: Polars in five minutes

You already used it in `report.py`. Polars is a DataFrame library like pandas, written in Rust: much faster, stricter about types, and built around **expressions** — `pl.col("units") * pl.col("unit_price")` describes a computation, and Polars runs it in an optimised plan — instead of pandas' chained indexing. Coming from pandas, the three habits to relearn:

| pandas | Polars |
|---|---|
| `df[df["product"] == "tea"]` | `df.filter(pl.col("product") == "tea")` |
| `df["revenue"] = df["units"] * df["unit_price"]` | `df.with_columns((pl.col("units") * pl.col("unit_price")).alias("revenue"))` |
| `df.groupby("region")["revenue"].sum()` | `df.group_by("region").agg(pl.col("revenue").sum())` |

Try it live:

```bash title="Any terminal, inside cours-agents"
uv run python -c "import polars as pl; df = pl.read_csv('sales.csv'); print(df.describe())"
```

Read next: [Polars — Coming from pandas](https://docs.pola.rs/user-guide/migration/pandas/). The [stretch exercise](#exercises) times the two libraries on a larger file.

## 8. When things go wrong

| Symptom | Cause | Fix |
|---|---|---|
| `uv: command not found` right after installing | PATH is read when a terminal starts | Open a new terminal. Still nothing on WSL/Mac: `source ~/.bashrc` (or `~/.zshrc`) |
| `uv init` says a `pyproject.toml` already exists | You ran it twice | Nothing to do |
| Your `uv.lock` differs from a classmate's for the same `pyproject.toml` | Different Python pinned | Both check `cat .python-version`; it must say `3.12` |
| `No module named polars` | You ran `python report.py` instead of `uv run report.py` | Always `uv run` |
| `git status` shows hundreds of files under `.venv` | `.gitignore` missing `.venv/` | `echo ".venv/" >> .gitignore`, then `git status` again |
| `echo $UNISTRA_API_KEY` is empty in a new window | Line went in the wrong startup file, or the window is not new | `echo $SHELL`; `bash` → `~/.bashrc`, `zsh` → `~/.zshrc`; redo [setup 5.2](../setup.md#52-store-it-as-an-environment-variable) |
| `Failed to hardlink files; falling back to full copy` warning | Cache and project on different drives (e.g. work kept under `/mnt/c` in WSL) | Harmless. Better: keep projects in `~` — see [where to keep your work](../wsl.md#where-to-keep-your-work) |
| Arguments with spaces or `*` behave oddly | Shell quoting | Quote them: `--product "green tea"` |

## 9. Cheat sheet

| Command | What it does |
|---|---|
| `uv init --no-package --python 3.12` | New project in the current folder, flat layout, Python pinned |
| `uv add <pkg>` / `uv remove <pkg>` | Declare / undeclare a dependency (updates `pyproject.toml` and `uv.lock`) |
| `uv run <script.py> [args]` | Run inside the project's environment (creates it if needed) |
| `uv sync` | Rebuild `.venv` exactly from `uv.lock` |
| `uv tree` | Show installed packages and their dependencies |
| `uv python install 3.12` | Fetch a Python version (usually implicit) |
| `export NAME="value"` | Set a variable for this window |
| `echo 'export NAME="value"' >> ~/.bashrc` | …for every future window (`~/.zshrc` on Mac) |
| `echo $NAME` / `env` | Read one / all variables |
| `os.environ.get("NAME")` | Read it from Python (`None` if unset) |
