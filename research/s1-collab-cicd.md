Beginner-level summary that the sources support: *CI = everyone merges into one mainline at least daily, and a machine that is not yours builds and tests every push, so "works on my machine" is caught in minutes rather than months. CD = the tested result is always releasable (delivery) or is released automatically (deployment).*

The two consequences for the page: (1) CI is the check the agent cannot skip, because it runs on a machine the agent does not control and on the commit that was pushed, not on the agent's claim; (2) CI only has teeth if the tests are committed **before** the agent runs and the agent is told not to touch them — a test the agent can rewrite is not a test.

### 5b. The workflow file (every tag verified 2026-09-14; YAML parsed; both commands rehearsed)

```yaml title=".github/workflows/tests.yml"
name: tests
on:
  push:
  pull_request:
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7            # latest major, 2026-07-20
      - uses: astral-sh/setup-uv@v10.1.0     # setup-uv publishes no @v10 tag — pin the full version
      - run: uv sync --locked                # fails if uv.lock is missing or stale
      - run: uv run pytest
```

Flags: `--locked` is documented on the uv GitHub-integration page and in `uv sync --help` (0.12.10). `uv sync` installs the `dev` group (pytest) by default, so `--dev` is not needed; `--all-extras` from uv's recipe is dropped because `agent-lab` has no extras. `uv python install` is unnecessary: `uv sync` reads `.python-version` and installs that interpreter (rehearsed: `Using CPython 3.12.x`). Optional: `with: enable-cache: true` under `setup-uv` (documented) — omit for the reading.

### 5c. Vocabulary rows to add to §7

| Word | Meaning |
|---|---|
| **job** / **step** / **runner** | A job is a list of steps run on one fresh virtual machine (the runner); a step is one command or one reusable action |
| **action** (`uses:`) | A reusable step published by someone else, e.g. `actions/checkout`, `astral-sh/setup-uv`, browsable on the GitHub Marketplace; always pin a version |
| **status check** | The green check / red cross a workflow reports on a commit or PR; blocks merging only if the repository's ruleset says "Require status checks to pass" |
| **ruleset** | Repository rules on a branch (Settings → Rules → Rulesets): require a PR, require checks to pass |
| **continuous delivery** vs **continuous deployment** | Always *able* to release (delivery) vs every green `main` *is* released (deployment) |
| **pipeline** (GitLab) | GitLab's word for a workflow run; configured in `.gitlab-ci.yml`; "Pipelines must succeed" is its merge gate |

## 6. Risks and what NOT to say

- **Do not say a red cross blocks merging.** It blocks only under a ruleset / branch protection; say "GitHub can be told to refuse the merge" and give the path.
- **Do not write `astral-sh/setup-uv@v10` or `@v9`.** No such tags; the action's own release notes call major tags a supply-chain risk. Do not SHA-pin on the page either (unreadable for beginners) — full version tag plus comment.
- **Do not say "free"** without the qualifier: unlimited for public repos; 2,000 min/month on private repos under GitHub Free. Do not quote the 2×/10× OS multipliers from memory; the per-minute prices above are what the page shows today.
- **Do not promise Hugging Face Spaces as a free app host.** Since the docs' current wording, Gradio/Docker Spaces need a paid plan except two ZeroGPU Gradio Spaces per personal account; static Spaces stay free.
- **Do not claim economists use CI.** The AEA policy and the Data Editor's 2026 guidance do not mention it; the honest sell is "your replication package checked by a robot before the data editor does".
- **Do not call DORA's metrics "the four keys" without a hedge**; the page lists five (updated 2026-01-05).
- **Do not date Fowler's article to 2006** — 2000 original, 2006 revision, 2024 rewrite; the quotes above are from the 2024 text.
- **Do not present Anthropic's TDD steps as current wording**: the "not to modify the tests" sentence lives in the 2025 post (archived); the live page says "Give Claude a way to verify its work" and "If you can't verify it, don't ship it".
- **Do not let the reading grow into a tutorial.** One workflow file, one hands-on step, no caching, no matrices, no secrets; secrets belong in S3 (`.env`) and never in a workflow file on a public repo.
- **Do not skip the `workflow` token scope caveat** in 5d; it is the one thing that silently fails.
