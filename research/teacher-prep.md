## The five questions (answers to give, one paragraph each)

**"Why is this dumber than ChatGPT?"** — Because it is smaller and runs on the university's hardware: the models you are calling activate 3–6 billion parameters per token; the model behind ChatGPT is much larger, is wrapped in a product (retrieval, tools, memory, a tuned system prompt), and you never see its raw API. What you are looking at is the raw HTTP call with nothing around it — which is the point: everything that makes a chatbot feel smart is engineering we will add ourselves in Session 4. Also: the free Unistra service may silently fall back to a 3B model under load; check `usage` and the answer quality before blaming yourself.

**"Is it reading my files?"** — Only what is in `messages`. The model sees exactly the bytes you POST, nothing else, and forgets them when the response ends (Session 3.2). In OpenCode, files reach the model only when a tool (`read`, `bash`, `grep`) returns them — and permissions decide whether that tool may run. The Unistra platform is self-hosted at the university; check the [FAQ](https://documentation.unistra.fr/DNUM/Intelligence_artificielle/guide_complet_IA/co/9-FAQ.html) on data retention before pasting sensitive data, and never put an API key or personal data in a prompt you would not put in an email.

**"Can I just use Copilot / Cursor / ChatGPT?"** — Yes, and after this course you will understand what they hide: a system prompt, a context assembly strategy, tools, permissions, and a loop. The course uses raw curl and OpenCode because you can *see* those layers and swap the model; the skills transfer, the config file does not. For the exam, any harness is fine as long as you can explain the loop and show git history of what the agent did.

**"Why does it forget what I said?"** — It never remembered. Each request is a fresh function call; "memory" is your client resending the history. Long chats cost more tokens and eventually exceed the context window (32k–262k here depending on the model), at which point the client truncates or summarizes — that is when "it forgot".

**"Can I trust its code / results?"** — Trust the tests, not the model. The most reliable component in an agent system is the test suite plus git: assertions before code, `git diff` before commit, and a discrepancy is a finding, not a bug to be "fixed" quietly. The empirical literature (Brodeur et al. 2025: AI-led reproduction teams succeeded 57 pp less often than humans) says structure and human review, not model size, carry the reliability.
