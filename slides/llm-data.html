Two ideas for the whole session

1

From unordered to ordered. Free text, misspelled names, a scanned page → a clean column, a code, a table.

2

Almost zero examples. The model has already read billions of sentences: a one-paragraph instruction is enough for a first prototype.

text, names, images  →  LLM + an instruction  →  labels, codes, columns

Before LLMs · 1/2

First, label thousands of headlines by hand

textlabel
ECB keeps interest rates unchangedeconomy
Parliament votes on the pension reform billpolitics
Strasbourg wins 2-0 against Lyonsport
Unemployment falls to its lowest level in ten yearseconomy
… 2,000 more rows, each read and labelled by a person ……
 
2,000 labelled headlines  →  80 % train set  (the model learns from these)
                          →  20 % test set   (hidden, used only to measure the score)

The model starts from nothing: everything it knows comes from your labels.

Before LLMs · 2/2

Then train, then test

from sklearn.model_selection import train_test_split
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression

# 1. split the labelled table: 80 % to learn, 20 % to check
X_train, X_test, y_train, y_test = train_test_split(texts, labels, test_size=0.2)

# 2. words → numbers
words = TfidfVectorizer().fit(X_train)

# 3. learn which words go with which class
model = LogisticRegression().fit(words.transform(X_train), y_train)

# 4. score on headlines the model has never seen
print(model.score(words.transform(X_test), y_test))

No labels, no model. The expensive part is the labelling, not the computing.

2 — A workflow · the data

One positive effect, one mixed effect

A · Smart irrigation

Farmers face a shortage of water while the demand for food keeps rising. We introduce AIDSII, an app that combines IoT sensors with deep learning models to decide when and how much to irrigate. It reduces water waste and improves yields.

B · Bitcoin in Texas

Supporters of Bitcoin claim that miners' demand for electricity leads to more renewable capacity. We add a Bitcoin demand curve to a model of the Texas electricity market. Mining does increase renewable capacity, but it also increases carbon emissions.

2 — A workflow · two passes

Cast a wide net, then check

pass 1 (broad)   →  SDG2, SDG6, SDG9
pass 2 (check)   →  SDG2 Y   SDG6 Y   SDG9 N
kept             →  SDG2, SDG6       = the expected answer
A screening step proposed the label {code} for this abstract. Your job is to check.
Answer Y when what the paper studies really bears on it. Answer N when the link is only
a passing mention, a word used in another sense, or a generic claim of benefit.

One broad question, then closed questions: each is easier than everything at once.

3 — An agent

An agent is a loop

messages = [{"role": "user", "content": TASK}]
for step in range(15):                         # cap: no infinite loop
    reply = chat(messages, tools=TOOLS)        # the model answers…
    if not reply.tool_calls:                   # …with text: it is done
        break
    for call in reply.tool_calls:              # …or with tool requests
        result = run_tool(call)                # OUR code runs the tool
        messages.append(tool_message(result))  # and sends the result back

The model decides what to do. Your code does it.

3 — An agent · the tools

age_at, in full

Our code runs this

from datetime import date

def age_at(birth_date: str, event_date: str) -> str:
    birth = date.fromisoformat(birth_date)
    event = date.fromisoformat(event_date)
    # True (= 1) if the birthday has not come yet that year
    before = (event.month, event.day) < (birth.month, birth.day)
    return str(event.year - birth.year - before)

The model reads this

{"name": "age_at",
 "description":
   "Age in years between two dates.",
 "parameters": {
   "birth_date": "YYYY-MM-DD",
   "event_date": "YYYY-MM-DD"}}

Docs: date.fromisoformat

model asks:  age_at({"birth_date": "1972-10-25", "event_date": "2019-10-14"})
we send back: '46'

The model never sees the code, only what is on the right.

4 — Evaluate

Everything is at 100%. Be suspicious.

Small, clean examples, chosen by me. Your real data will be messier.

A column produced by an LLM is a measurement. Before using it, measure its error.

4 — Evaluate
