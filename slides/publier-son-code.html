1 — La documentation

Un site web, ce sont des fichiers

uv run pdoc -d google strong_password.py strength.py -o site
ls site
index.html  search.js  strength.html  strong_password.html

Quatre fichiers. Pas de serveur, pas de base de données. N'importe quel hébergeur de fichiers peut les servir.

On ne versionne pas site/ : on peut le regénérer. Il reste à le regénérer et le publier à chaque modification — sans y penser.

2 — CI/CD

Un robot qui travaille à chaque push

CI — intégration continue

À chaque push, une machine de GitHub récupère le code et lance les tests.

Fini « ça marche chez moi ».

CD — déploiement continu

Si les tests passent, la même machine construit et publie : ici, la doc.

Personne ne lance rien à la main.

git push  →  test  →  docs  →  deploy  →  knuxv.github.io/password-app

Le robot est décrit dans un fichier du dépôt : .github/workflows/ci.yml.

2 — CI/CD · .github/workflows/ci.yml (extrait)

Le fichier du robot

on:
  push:
    branches: [main]            # quand : à chaque push sur main

jobs:
  test:
    runs-on: ubuntu-latest      # une machine Linux prêtée par GitHub
    steps:
      - uses: actions/checkout@v7          # récupérer le code
      - uses: astral-sh/setup-uv@v10.3.0   # installer uv
      - run: uv sync
      - run: uv run pytest                # la même commande que vous

  docs:
    needs: test                 # seulement si les tests passent
    steps:
      - run: uv run pdoc -d google strong_password.py strength.py -o site
      - uses: actions/upload-pages-artifact@v5

3 — Site statique

Statique ou dynamique ?

Statique

Le serveur envoie des fichiers, les mêmes pour tout le monde.

La doc pdoc, un CV, un blog, le site du cours.

Hébergement : GitHub Pages, gratuit.

Dynamique

Un programme tourne sur le serveur et calcule chaque page.

Une appli Streamlit, un formulaire, une recherche.

Il faut une machine qui reste allumée.

3 — Site statique · .github/workflows/bundle.yml

Un robot qui fabrique un fichier

on: push
jobs:
  bundle:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - run: sudo apt-get update && sudo apt-get install -y pandoc
      - run: pandoc index.md a-propos.md notes.md -s -o site.html
      - run: pandoc index.md a-propos.md notes.md -o site.docx
      - uses: actions/upload-artifact@v7    # garder les fichiers
        with:
          name: site
          path: |
            site.html
            site.docx

Votre directeur de mémoire veut un .docx ? Le robot le refait à chaque push.

4 — Streamlit

Un script Python devient une page web

git diff step-2 step-3 --stat

 pyproject.toml    |   1 +
 tests/test_app.py |  16 +
 uv.lock           | 944 +++++++++++++++++++++++++++++++
 5 files changed, 1001 insertions(+), 1 deletion(-)

Une dépendance (uv add streamlit), un fichier app.py. Pas de HTML, pas de JavaScript.

Le générateur ne change pas. L'appli ne fait que l'appeler. (Les 944 lignes de uv.lock : Streamlit et ses dépendances, à la version près.)

4 — Streamlit · app.py (extrait)

Toute l'appli

import streamlit as st

st.title("Password generator")

kind = st.radio("Kind", ["memorable", "random"], horizontal=True)
if kind == "memorable":
    length = st.slider("Number of words", min_value=3, max_value=10, value=5)
else:
    length = st.slider("Number of characters", min_value=8, max_value=40, value=16)

password = StrongPassword(length=length, type_p=TypePassword(kind)).generate()
st.code(password, language=None)      # avec un bouton « copier »

strength = check_strength(password)
st.metric("Score", f"{strength.score} / 4")
st.write(f"Time to crack it: **{strength.crack_time}**")
st.button("Another one")

4 — Streamlit · tout le monde

Lancer l'appli

uv run streamlit run app.py
  You can now view your Streamlit app in your browser.

  Local URL: http://localhost:8501

Le navigateur s'ouvre. Bougez le curseur, changez de type, cliquez Another one.

localhost = votre machine. Personne d'autre ne voit l'appli. Ctrl+C pour l'arrêter.

4 — Streamlit

Chaque clic relance tout le script

clic  →  app.py de la ligne 1 à la fin  →  la page redessinée
         kind et length ont leurs nouvelles valeurs

C'est pour ça que st.button("Another one") marche sans code : cliquer relance le script, donc generate() est rappelé.

Un calcul lent est refait à chaque clic. Pour l'éviter : @st.cache_data.

4 — Streamlit · tests/test_app.py

Une appli, ça se teste

from streamlit.testing.v1 import AppTest

def test_switching_to_random_changes_the_slider() -> None:
    app = AppTest.from_file("../app.py").run()      # sans navigateur
    app.radio[0].set_value("random").run()          # « cliquer »
    assert app.slider[0].label == "Number of characters"
    assert len(app.code[0].value) == 16

Ces tests tournent aussi dans le robot : une appli cassée ne passe pas.

4 — Streamlit · bonus

La mettre en ligne

GitHub Pages ne sert que des fichiers : il ne peut pas faire tourner Python.

1

share.streamlit.io → se connecter avec GitHub.

2

Choisir le dépôt, la branche main, le fichier app.py.

3

Il lit uv.lock et installe les mêmes versions que chez vous.

Gratuit, pour un dépôt public. Parfait pour une démo d'examen.

5 — Licences

Public ≠ libre

Sans licence, votre code est sous droit d'auteur exclusif, même sur un dépôt public.

« Nobody else can copy, distribute, or modify your work without being at risk of take-downs, shake-downs, or litigation. »

choosealicense.com/no-permission

GitHub permet de voir et de forker. Pour réutiliser, il faut une licence.
